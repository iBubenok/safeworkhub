# Требования и архитектура MVP

## Обзор MVP

MVP (Minimum Viable Product) SafeWorkHub — это первая версия платформы, обеспечивающая базовый функционал для специалистов по охране труда. Цель MVP — валидация бизнес-модели и получение обратной связи от первых пользователей.

## Целевая аудитория

### Первичные пользователи
- **Специалисты по охране труда** — основные пользователи системы
- **Руководители служб ОТ** — управление командой, отчётность
- **HR-специалисты** — организация обучения сотрудников

### Вторичные пользователи
- **Сотрудники организаций** — прохождение обучения по ОТ
- **Руководители подразделений** — контроль обучения подчинённых

## Роли и права доступа

## Функциональные требования

### Модуль 1: Аутентификация и управление доступом

#### FR-AUTH-001: Регистрация организации
**Приоритет:** Критический

**Описание:** Система должна позволять регистрацию новых организаций с автоматическим созданием администратора.

**Сценарий:**
1. Пользователь заполняет форму регистрации (название организации, ИНН, email, пароль)
2. Система проверяет уникальность email и ИНН
3. Создаётся организация и пользователь с ролью Organization Admin
4. Отправляется письмо для подтверждения email
5. После подтверждения активируется пробный период

**Критерии приёмки:**
- [ ] Валидация email (формат, уникальность)
- [ ] Валидация ИНН (формат, контрольная сумма)
- [ ] Создание организации в статусе "trial"
- [ ] Отправка confirmation email
- [ ] Redirect на dashboard после подтверждения

#### FR-AUTH-002: Аутентификация пользователя
**Приоритет:** Критический

**Описание:** Пользователи должны иметь возможность входа по email и паролю.

**Сценарий:**
1. Пользователь вводит email и пароль
2. Система проверяет учётные данные
3. При успехе выдаются access и refresh токены
4. Пользователь перенаправляется на dashboard

**Критерии приёмки:**
- [ ] Выдача JWT access token (TTL: 15 минут)
- [ ] Выдача refresh token (TTL: 7 дней, httpOnly cookie)
- [ ] Блокировка после 5 неудачных попыток (30 минут)
- [ ] Логирование попыток входа

#### FR-AUTH-003: Управление пользователями организации
**Приоритет:** Высокий

**Описание:** Администратор организации должен иметь возможность приглашать пользователей и управлять их ролями.

**Сценарий:**
1. Администратор вводит email нового пользователя и выбирает роль
2. Система отправляет приглашение на email
3. Пользователь переходит по ссылке и устанавливает пароль
4. Учётная запись активируется

**Критерии приёмки:**
- [ ] Приглашение по email
- [ ] Выбор роли при приглашении
- [ ] Срок действия приглашения — 7 дней
- [ ] Возможность отзыва приглашения

### Модуль 2: База знаний

#### FR-KB-001: Каталог материалов
**Приоритет:** Критический

**Описание:** Система должна предоставлять структурированный каталог материалов по охране труда.

**Категории материалов:**
- Нормативно-правовые акты
- Экспертные рекомендации
- Шаблоны документов
- Справочники и таблицы
- Профессиональные статьи

**Критерии приёмки:**
- [ ] Иерархическая структура категорий (до 3 уровней)
- [ ] Фильтрация по типу материала
- [ ] Фильтрация по тематике (промбезопасность, пожарная безопасность и т.д.)
- [ ] Сортировка по дате, популярности, релевантности

#### FR-KB-002: Полнотекстовый поиск
**Приоритет:** Критический

**Описание:** Пользователи должны иметь возможность искать материалы по текстовому запросу.

**Сценарий:**
1. Пользователь вводит поисковый запрос
2. Система выполняет полнотекстовый поиск
3. Результаты ранжируются по релевантности
4. Отображаются сниппеты с подсветкой найденных слов

**Критерии приёмки:**
- [ ] Поиск по заголовкам и содержимому
- [ ] Морфологический анализ (русский язык)
- [ ] Подсветка найденных терминов
- [ ] Время отклика < 500ms для 90% запросов

#### FR-KB-003: Просмотр и скачивание документов
**Приоритет:** Высокий

**Описание:** Пользователи должны иметь возможность просматривать материалы и скачивать шаблоны.

**Критерии приёмки:**
- [ ] Просмотр HTML-контента в браузере
- [ ] Скачивание шаблонов в форматах DOCX, XLSX, PDF
- [ ] Учёт скачиваний для аналитики
- [ ] Watermark с названием организации для шаблонов

### Модуль 3: Система обучения (LMS)

#### FR-LMS-001: Каталог курсов
**Приоритет:** Высокий

**Описание:** Система должна предоставлять каталог онлайн-курсов по охране труда.

**Структура курса:**
- Название, описание, длительность
- Целевая аудитория
- Модули (последовательность уроков)
- Итоговое тестирование
- Сертификат по завершении

**Критерии приёмки:**
- [ ] Список курсов с фильтрацией по категориям
- [ ] Карточка курса с детальной информацией
- [ ] Отображение прогресса для начатых курсов

#### FR-LMS-002: Прохождение обучения
**Приоритет:** Высокий

**Описание:** Пользователи должны иметь возможность проходить курсы и отслеживать прогресс.

**Сценарий:**
1. Пользователь начинает курс
2. Последовательно изучает модули
3. После каждого модуля проходит промежуточный тест
4. По завершении всех модулей сдаёт итоговый экзамен
5. При успешной сдаче получает сертификат

**Критерии приёмки:**
- [ ] Сохранение прогресса между сессиями
- [ ] Блокировка следующего модуля до завершения текущего
- [ ] Ограничение времени на тестирование
- [ ] Минимум 80% правильных ответов для успешной сдачи

#### FR-LMS-003: Назначение обучения
**Приоритет:** Высокий

**Описание:** Руководители должны иметь возможность назначать курсы сотрудникам.

**Критерии приёмки:**
- [ ] Выбор курса и сотрудников для назначения
- [ ] Установка дедлайна прохождения
- [ ] Email-уведомление о назначении
- [ ] Напоминания о приближающемся дедлайне

#### FR-LMS-004: Отчётность по обучению
**Приоритет:** Средний

**Описание:** Система должна формировать отчёты о прохождении обучения.

**Типы отчётов:**
- Сводка по организации (кол-во обученных, в процессе, просроченных)
- Отчёт по сотруднику (пройденные курсы, результаты)
- Отчёт по курсу (статистика прохождения)

**Критерии приёмки:**
- [ ] Выгрузка отчётов в Excel
- [ ] Фильтрация по периоду, подразделению, курсу
- [ ] Диаграммы и графики в интерфейсе

### Модуль 4: Подписка и биллинг

#### FR-SUB-001: Управление подпиской
**Приоритет:** Критический

**Описание:** Система должна управлять подписками организаций.

**Модель подписки MVP:**
- Единый тариф с ежемесячной/годовой оплатой
- Стоимость зависит от количества пользователей
- 14-дневный пробный период

**Критерии приёмки:**
- [ ] Отображение текущего статуса подписки
- [ ] Информация о дате окончания
- [ ] Возможность изменения количества пользователей
- [ ] Уведомления об окончании подписки

#### FR-SUB-002: Ограничения по подписке
**Приоритет:** Критический

**Описание:** Доступ к функциям системы должен ограничиваться в зависимости от статуса подписки.

**Критерии приёмки:**
- [ ] Полный доступ для активной подписки
- [ ] Ограниченный доступ в пробном периоде
- [ ] Блокировка входа при неоплаченной подписке
- [ ] Grace period 7 дней после окончания

## Пользовательские сценарии (User Stories)

### Epic: Регистрация и онбординг

**US-001: Как представитель компании, я хочу зарегистрировать организацию, чтобы получить доступ к системе**

Критерии приёмки:
- Могу зарегистрироваться, указав данные организации
- Получаю email для подтверждения
- После подтверждения попадаю на dashboard
- Вижу информацию о пробном периоде

**US-002: Как администратор, я хочу пригласить коллег в систему, чтобы они могли пользоваться платформой**

Критерии приёмки:
- Могу ввести email и выбрать роль
- Коллега получает приглашение
- После принятия коллега появляется в списке пользователей

### Epic: Работа с базой знаний

**US-003: Как специалист по ОТ, я хочу найти информацию по конкретному вопросу, чтобы подготовить обоснованное решение**

Критерии приёмки:
- Могу ввести запрос на естественном языке
- Получаю релевантные результаты
- Вижу ссылки на НПА и экспертные рекомендации

**US-004: Как специалист по ОТ, я хочу скачать шаблон документа, чтобы адаптировать его для своей организации**

Критерии приёмки:
- Могу найти нужный шаблон в каталоге
- Могу просмотреть превью
- Могу скачать в удобном формате

### Epic: Обучение сотрудников

**US-005: Как руководитель, я хочу назначить обучение сотрудникам, чтобы обеспечить соответствие требованиям ОТ**

Критерии приёмки:
- Могу выбрать курс из каталога
- Могу выбрать сотрудников для назначения
- Могу установить срок прохождения
- Сотрудники получают уведомления

**US-006: Как сотрудник, я хочу пройти назначенный курс, чтобы выполнить требования по обучению**

Критерии приёмки:
- Вижу список назначенных курсов
- Могу проходить уроки последовательно
- Могу сдать тест по завершении
- Получаю сертификат при успешной сдаче

### Epic: Управление подпиской

**US-007: Как администратор, я хочу видеть статус подписки, чтобы планировать бюджет и продление**

Критерии приёмки:
- Вижу текущий тариф и стоимость
- Вижу дату окончания подписки
- Вижу количество используемых лицензий
- Могу запросить счёт на продление

## Зависимости и риски

### Внешние зависимости

| Зависимость | Риск | Митигация |
|-------------|------|-----------|
| Платёжный провайдер | Интеграция может занять время | Начать с ручного выставления счетов |

| Email-провайдер | Возможны проблемы доставки | Использовать проверенный сервис |

| Риск | Вероятность | Влияние | Митигация |

| Сложность миграции данных | Низкая | Среднее | Версионирование схемы |
| Уязвимости безопасности | Средняя | Критическое | Security review, тесты |
